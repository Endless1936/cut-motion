# cut-motion Agent Protocol

@/Users/prototech/.codex/RTK.md

cut-motion is an Agent workflow for turning a talking-head recording into a tightly edited, motion-designed video. This file is the always-loaded entry point; phase instructions live in `docs/`.

## Always-loaded rules

- Resume from the active job's `state/workflow.json`. Read its status once on entry or resume with `node scripts/workflow-state.mjs <path> status`; do not poll between known steps.
- In [`docs/workflow.md`](docs/workflow.md), read the route for the current state and its phase section only. Reuse guidance already read while staying in that phase; load a linked specialist guide when the phase needs it. Open [`docs/troubleshooting.md`](docs/troubleshooting.md) only when a matching failure occurs.
- A local talking-head video is required. If it is missing, ask for its path and stop. Honor preferences the user already supplied; otherwise use job defaults and do not pause for an optional-preference round.
- Preserve the source video. Keep each job's media, state, previews, and logs inside its job directory; keep private job data and credentials out of Git. Run the repository privacy check before committing examples or workflow changes.
- Keep repository documentation reusable: put execution rules in the existing phase or specialist guide. Do not add one-off audit reports, review summaries or optimization logs outside jobs; report findings in chat.
- The recording is authoritative for spoken wording. Reconcile any supplied reference script against it; `【】` holds visual notes, while ordinary `[]` remains spoken text. See the workflow guide for handling and provenance.
- Do not ask the user for item-by-item listening before the rough cut. Prepare the rough cut from ChatCut transcription and timing; the user listens to the complete cut in the existing `rough-cut-review` and explicitly approves or requests revisions.
- Delivery targets: rough cut in 30 minutes, three plans normally in about 10 minutes and at most 15 minutes after rough-cut approval, and final export within a further 15 minutes (60 minutes total, excluding time waiting for the user). These are execution targets, not workflow gates. If a route stalls, continue independent work and promptly report the current stage, actual impact, and one concrete next step.
- Rough-cut delivery is one semantic edit, one pause-cleanup batch, and one calculated edge-tightening batch before sharing the ChatCut project link. If using `clean_script`, run it only for silence with `only:"silence"`; after the first two edits, save one timeline snapshot and run `node scripts/prepare-rough-cut.mjs <job> tighten <snapshot>` once, then apply its plan once. When useful, use at most one read-only sub-agent to identify pause candidates during the semantic pass; the main agent alone edits ChatCut. While the user listens, prepare only key MG content/template choices and real exceptions. After approval, start or resume one A-roll export, reusing any existing output or running task. In parallel, preview the approved main timeline once; use `transcript.entries[].text`, `timelineRange` and FPS for plan text and timing. Follow `nextOffset` only when returned, passing it as `offset` with the returned timeline ID and same filters; save every page's `structuredContent` in order as an array in `state/chatcut-main-timeline.json`. Bind `sourceSegmentIds` and anchors to generated `main-001`, `main-002`, etc. in preview order, not ChatCut item IDs or Script row numbers. Use the existing plan input to author natural phrase-level caption cues with text and start/end times inside their parent main-timeline entry; follow `docs/subtitle-segmentation-standard.md`. Generate and deliver Caption, Motion and Creative Confirmation plans together in one pass while export runs. Use the existing main-timeline text and timing; source-word lookup and render setup are not needed for routine plans. Composition waits for plan-package approval and the A-roll media lock.
- Use `scripts/workflow-state.mjs` for every state transition. In `review`, wait for user approval at `rough-cut-review`, then deliver the three plans immediately after generation and wait for one package approval. Keep `rough-cut-export` until this job's confirmed export is promoted and locked, then advance to `motion-plan`; retain any package approval already received. Call `compose-job.mjs` only after package approval and the A-roll media lock. `auto` skips the package wait only when explicitly selected. Never infer approval or Auto mode. Follow the active phase's few checks; do not run a separate full audit during routine delivery.
- Use the phase's existing generators for candidate records, plans and template assembly; author content decisions once. Follow the current phase guide for commands and scoped revisions.
- Use ChatCut for the editable rough cut, FFmpeg/FFprobe for media work, and HyperFrames HTML/CSS/GSAP for captions, motion, composition, and rendering. Remotion or Vibe Motion requires an explicit user request; record any execution deviation internally for diagnosis. User-facing status updates must not label work as an execution deviation; state the current stage, actual impact, and next step.
- During planning, choose a [motion template](templates/motion-graphics/README.md) and record its ID; during composition, instantiate that planned template. Use a custom MG when the content or an explicit design request needs it, with a brief reason in the Motion Plan.
- Before full export, inspect each MG's fully expanded final HTML snapshot and fix visual issues using [MG final-state self-review](docs/workflow.md#mg-final-state-self-review). This is Agent work, with no machine gate or extra user approval.
- Place A-roll MG in the upper-middle area by default (templates start at 280px on a 1080×1920 canvas). Keep the overall MG and its background card horizontally centered on the video canvas; internal text and rows may align left or right. Adapt height and width to avoid captions without shifting the card to a corner. Eyes and mouth do not need clearance. Preserve the spoken item count and causal direction. From the first composition, reveal two or more independent elements at their actual spoken keyword onsets using [existing word timing](docs/mg-speech-timing.md), with a designed exit; sample intervals are demonstrations. These are authoring requirements within the existing phases, not extra approvals or gates.
- Start each new job with `./scripts/scaffold-project.sh jobs/<job-id> /absolute/path/to/video.mov review`, then run `./scripts/check-environment.sh check` once. For same-machine hosted ChatCut import, use the bundled local-media helper with `import_media action=from_editor`; use `create_session` and its matching upload helper only when that route is unavailable. If ChatCut reports the asset is ready or already exists, reuse it and continue to transcript readiness instead of uploading it again. Follow [`docs/agent-setup.md`](docs/agent-setup.md) for client-specific arguments. If ChatCut is unavailable, report it immediately; do not enumerate tools or investigate endpoints during normal editing. **Project-local HyperFrames/GSAP installation is not approval-gated:** run `./scripts/check-environment.sh install-job <job-directory>` without asking; it reuses `.cache/cut-motion/node_modules` and installs the pinned versions there if absent. Ask only before installing global/system dependencies, changing global Agent configuration, or starting OAuth.
