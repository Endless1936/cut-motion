# cut-motion Agent Protocol

@/Users/prototech/.codex/RTK.md

Use ChatCut for an editable rough cut and HyperFrames HTML/CSS/GSAP for captions, MG and delivery. Phase commands live in [the workflow guide](docs/workflow.md).

- Resume the existing job: read `state/workflow.json` with `scripts/workflow-state.mjs ... status` once, then load only the current phase. Reuse media, plans, exports and dependencies; use the existing transition helpers instead of editing status manually. Read troubleshooting only for a matching failure.
- Require a local source video and preserve it. Honor supplied preferences; otherwise use job defaults without a preference round. Store private media, transcripts and generated files in `jobs/`, outside Git. Keep reusable instructions and tests in the repository; report one-off findings in chat.
- For an ordinary two-minute talking-head video, target rough cutting within 6 minutes, the combined plans within 4 minutes and finishing within 8 minutes: total execution within 18 minutes, excluding user review/reply waits. Preparation, tool runtime and recovery belong inside these phase budgets. This is an execution preference, not a gate or a measured guarantee; report a stalled route's impact and continue independent work.
- Review waits twice: after the complete rough cut, then after the combined Caption Plan, Motion Plan and Creative Confirmation. Retain approvals already given. Explicit Auto skips user waiting with the same creative defaults. Start or reuse the clean A-roll export as soon as the cut is approved, and prepare plans in parallel.
- Rough cut once: semantic edit, silence-only cleanup (`only:"silence"`), then `prepare-rough-cut.mjs ... tighten` and one calculated editing batch. Follow [the trim standard](docs/talking-head-trim-standard.md). Wide ASR intervals alone do not justify restoring edges; global audio smoothing is not a default step. Share the confirmed cut immediately, with no separate per-seam listening round.
- Author wording and design decisions once in `state/planning-inputs.json`; tools generate the related files. Reconcile retained speech with the supplied reference before plan delivery. The recording is authoritative; `【】` holds visual notes and ordinary `[]` remains spoken text. Supply terminology corrections and short phrase arrays only for entries needing splits; reuse existing timing instead of hand-calculating every cue or repeating ordinary reconciliation entries.
- Choose [MG templates](templates/motion-graphics/README.md) by meaning. Keep the card horizontally centered in the upper-middle area, at its final size from the first frame; avoid captions, with no eye or mouth clearance requirement. Independent elements enter at their spoken keywords. Spoken results belong in the result slot and enter when named, not in an early title. Use meaningful MG nodes rather than illustrating every subtitle.
- After approved plans and clean A-roll are ready, use `compose-job.mjs` once. Inspect each MG's fully expanded snapshot in one batch, repair and recapture affected groups, then use the normal render entrypoint once. Follow scoped revision commands; standalone audits and repeated full checks are diagnostics, not routine production steps.
- Keep complete tool responses in the job and let the helpers unwrap ChatCut data; return counts, paths, changed items and the next command. Reuse guidance already read; open implementation source only for an actual failure that the command output cannot resolve.
- Start new jobs with `scripts/scaffold-project.sh` and run `scripts/check-environment.sh check` once. Follow [client setup](docs/agent-setup.md) for ChatCut import, reusing ready assets and respecting upload authorization. Project-local pinned dependencies use the repository's `node_modules/`; `install-job` needs no extra approval. Global/system installation, global Agent configuration and OAuth require user authorization.
- Before committing workflow changes, run `bash scripts/verify-repository.sh` and the staged repository privacy check. These are development checks, not video-production steps. Do not add workflow states, approval receipts, audit reports or automatic quality gates.
