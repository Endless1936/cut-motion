# cut-motion Agent Protocol

@/Users/prototech/.codex/RTK.md

cut-motion is an Agent workflow for turning a talking-head recording into a tightly edited, motion-designed video. This file is the always-loaded entry point; phase instructions live in `docs/`.

## Always-loaded rules

- Resume from the active job's `state/workflow.json`. Read its status once on entry or resume with `node scripts/workflow-state.mjs <path> status`; do not poll between known steps.
- In [`docs/workflow.md`](docs/workflow.md), read the route for the current state and its phase section only. Reuse guidance already read while staying in that phase; load a linked specialist guide when the phase needs it. Open [`docs/troubleshooting.md`](docs/troubleshooting.md) only when a matching failure occurs.
- A local talking-head video is required. If it is missing, ask for its path and stop. Honor preferences the user already supplied; otherwise use job defaults and do not pause for an optional-preference round.
- Preserve the source video. Keep each job's media, state, previews, and logs inside its job directory; keep private job data and credentials out of Git. Run the repository privacy check before committing examples or workflow changes.
- The recording is authoritative for spoken wording. Reconcile any supplied reference script against it; `【】` holds visual notes, while ordinary `[]` remains spoken text. See the workflow guide for handling and provenance.
- Do not ask the user for item-by-item listening before the rough cut. Prepare the rough cut from ChatCut transcription and timing; the user listens to the complete cut in the existing `rough-cut-review` and explicitly approves or requests revisions.
- Delivery targets: rough cut in 30 minutes, the three plans within 15 minutes after rough-cut approval, and final export within a further 15 minutes (60 minutes total, excluding time waiting for the user). If a route stalls, continue independent work and promptly report the current stage, actual impact, and one concrete next step.
- Rough-cut delivery is one semantic pass, pause cleanup and one edge-tightening pass, then the ChatCut project link. When useful, use at most one read-only sub-agent to identify pause candidates during the semantic pass; the main agent alone edits ChatCut. While the user listens, prepare only key MG content/template choices and real exceptions. After approval, start or resume one A-roll export, reusing any existing output or running task. In parallel, preview the approved main timeline; use `transcript.entries[].text`, `timelineRange` and FPS for plan text and timing. Follow `nextOffset` only when returned, passing it as `offset` with the returned timeline ID and same filters; save every page's `structuredContent` in order as an array in `state/chatcut-main-timeline.json`. Bind `sourceSegmentIds` and anchors to generated `main-001`, `main-002`, etc. in preview order, not ChatCut item IDs or Script row numbers. Initial MG timing uses the full entry range; the generated `:word-001` stands for that whole entry, and word-level lookup is only for a specific timing change after the user reviews the final video. Generate and deliver the three plans while export runs; plans need no source-word timing or render setup. Composition waits for approval and the A-roll media lock.
- Use `scripts/workflow-state.mjs` for every state transition. In `review`, wait for user approval at `rough-cut-review`, then deliver the three plans and wait for one package approval while the job remains at `motion-plan`; call `compose-job.mjs` only after approval. `auto` continues after plan generation only when the user explicitly selected it. Never infer approval or Auto mode. Follow the active phase's few checks; do not run a separate full audit during routine delivery.
- Use the phase's existing generators for candidate records, plans and template assembly; author content decisions once. Follow the current phase guide for commands and scoped revisions.
- Use ChatCut for the editable rough cut, FFmpeg/FFprobe for media work, and HyperFrames HTML/CSS/GSAP for captions, motion, composition, and rendering. Remotion or Vibe Motion requires an explicit user request; record any execution deviation internally for diagnosis. User-facing status updates must not label work as an execution deviation; state the current stage, actual impact, and next step.
- During planning, choose a [motion template](templates/motion-graphics/README.md) and record its ID; during composition, instantiate that planned template. Use a custom MG when the content or an explicit design request needs it, with a brief reason in the Motion Plan.
- Before a new job, use the ChatCut tools already exposed in the session and run `./scripts/check-environment.sh check` once. If ChatCut is unavailable, report it immediately; do not enumerate tools or investigate endpoints during normal editing. Consult [`docs/agent-setup.md`](docs/agent-setup.md) only for a specific setup or render failure. **Project-local HyperFrames/GSAP installation is not approval-gated:** run `./scripts/check-environment.sh install-job <job-directory>` without asking; it reuses `.cache/cut-motion/node_modules` and installs the pinned versions there if absent. Ask only before installing global/system dependencies, changing global Agent configuration, or starting OAuth.
